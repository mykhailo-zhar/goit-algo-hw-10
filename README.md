## Алгоритми Coin Change 

Порівняння трьох підходів до задачі розміну суми мінімальною кількістю монет:

| Function | Approach | Complexity |
| -------- | -------- | ---------- |
| `find_coins_greedy` | Greedy (найбільший номінал спочатку) | \(O(C \log C)\) |
| `find_min_coins_recursive` | Recursion + memoization (top-down DP) | \(O(C \cdot S)\) |
| `find_min_coins` | Bottom-up DP | \(O(C \cdot S^2)\)\* |

\*У поточній реалізації додатковий множник \(S\) з’являється через копіювання списку монет на кожному кроці.

\(C\) — кількість номіналів, \(S\) — сума.

### Example

Для `coins = [50, 25, 10, 5, 2, 1]` і `amount = 113` усі три функції дають той самий розподіл:

```python
{50: 2, 10: 1, 2: 1, 1: 1}
```

### Benchmark

Запуск:

```bash
python -m src.greedy
```

Параметри: `coins = [50, 25, 10, 5, 2, 1]`, `amount = 113`, `number = 1000` ітерацій (`timeit`).

| Function | Total time | Per call |
| -------- | ---------- | -------- |
| `find_coins_greedy` | 0.000583 s | 0.58 µs |
| `find_min_coins_recursive` | 0.159163 s | 159.16 µs |
| `find_min_coins` | 0.382419 s | 382.42 µs |

### Висновки


#### Жадібні та динамічні алгоритми
Отже, жадібний алгоритм хоч і не гарантує оптимального результату, але за BigO і метриками обходить обидва динамічні алгоритми через відсутність члену S, що при невеликій множині номіналів монет може істотно перевищувати C; та відсутності копіювань списків. 

Оптимальна імплементація алгоритма Coin Change із bottom-up DP, адаптована під задачу, показує себе набагато гірше ніж рекурсивна імплементація (у 2 рази).
